## CPA 模型目录自动同步（推理强度不再依赖手动同步）

- **问题**：① CPA openai 兼容（openai-compatibility）密钥下维护的模型，其推理强度不进对话框的推理强度选择项；② 必须进设置点「从 CPA 同步模型」后才能选推理强度。
- **现场核实**：直连本机 CPA（127.0.0.1:8317）验证——grok-shell UA 的 `/v1/models` 目录对全部 openai 兼容模型都带 `reasoning_efforts`（grok/deepseek/kimi/glm 全系），解析链（`parseModelReasoningEfforts` + `preferUnprefixedModels` 兄弟合并）没问题。真正断点：推理强度只存在 `CpaSupervisor` 的**内存缓存**里，只有手动同步按钮会调 `listModelCatalog()` 填缓存；`cpaModelCatalog` 处理器只读缓存 + SDK 合并，从不主动拉取——重启后缓存空了，对话框就显示「未同步」。
- **修复**（开 CPA 自动同步）：
  - 新模块 `cpa-model-sync.ts`：`applyCpaModelCatalog(catalog, settings)`——空目录不写（防 CPA 半启动清空单）、集合对比无变化不写、默认模型仍在列表则保留、变更才返回 true。
  - `index.ts`：`onStatusChange` 监听 CPA 状态，**非 ready → ready 跳变**时自动拉目录并写入 settings（有变更才广播 `IPC.settingsUpdated`，渲染端 Composer 随 `settings.models` 依赖自动刷新）；15 秒后再补一次，接住端口刚开、提供商（尤其 openai-compat 密钥）还没加载完的情况；`before-quit` 清定时器。
  - `ipc-handlers.ts`：`cpaModelCatalog` 处理器加 best-effort 实时拉取（打开模型菜单即同步，CPA 没开/无 token 时静默回退缓存），目录有变化经新增 ctx 回调 `onSettingsSynced` 广播；手动同步 `cpaSyncModels` 复用同一 helper（保留空目录报错）。
- **测试**：新增 `cpa-model-sync.test.ts` 5 例（空目录保护 / 无序幂等 / 新增保留默认模型 / 默认模型消失回退 / 带前缀 id 原样保留）。
