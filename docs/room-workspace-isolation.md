# 群聊工作区隔离评估

核查日期：2026-09-11。当前已按用户选择接入官方内置 Bash 沙箱；完整进程隔离方案暂缓。

## 当前采用：官方内置沙箱

所有携带 `pathJail` 的群聊执行查询，包括实际在成员电脑执行的远端席位，统一传入官方 SDK 的 `sandbox` 配置：启用沙箱、初始化失败即停止、禁止模型脱离沙箱重试、关闭沙箱自动审批，保持文件系统隔离且不启用弱化选项。应用不添加命令排除项。普通个人会话不强制加沙箱。

官方沙箱以执行查询的工作目录作为默认可写工作区。首次加入路径限制或修改工作区时，会重新启动查询；即使上一次准备失败，也会与实际运行的查询配置比较，避免继续使用原来的无沙箱进程。原有文件路径 hook 与群聊审批继续执行。

本次保留官方设置加载行为：用户、项目、本地以及管理员设置仍按官方规则生效。路径允许规则、额外目录和命令排除列表可能参与合并，因此此阶段不能声称实现了完全独立于本机配置的严格目录白名单；管理员配置仍是受信任边界。官方默认还允许会话临时目录写入，并不默认禁止读取整个工作区外部。本次不包含 MCP、扩展或完整 CLI 进程隔离。[官方沙箱权限范围](https://code.claude.com/docs/en/sandboxing)、[设置列表的合并规则](https://code.claude.com/docs/en/settings)

验证：相关测试覆盖群聊启用、个人会话保持不变、已有审批保留、会话复用与切换目录、准备失败后的重试、SDK 错误事件及异常传播；类型检查通过。使用当前打包的 Claude Code **2.1.220** 配合 SDK **0.3.220** 和相同沙箱配置，在独立临时配置目录实测启动：返回 `Sandbox required but unavailable`，原因是当前 Windows 会话的官方沙箱功能开关未启用。结果为 0 轮、0 次模型调用；没有退回无沙箱执行。UI 会说明沙箱不可用，不显示原始错误中关闭强制沙箱的建议。

这意味着当前原生 Windows 机器的群聊 Agent 会拒绝启动。接入官方 API 不等于在此平台启用了可用的隔离；需要支持官方沙箱的执行环境。尚未在 Linux/macOS 上实际验证 Python 间接越界写入，后续应在这些执行环境完成端到端验收。

## 本次已修改

群聊本机和远端席位的新会话直接包含完整的简短路径规则，不再要求读取 `room-workspace-guard`。应用启动时不再安装该 skill，而是清理内容与旧模板一致的用户级 `SKILL.md`；保留用户改写的文件、链接和同目录的其他文件。新安装不会生成该 skill。

升级后的应用启动时执行迁移，新席位会话使用新指令。已经存在的模型上下文仍可能记着旧指令；用户自行修改过的同名 skill 不自动删除，需另行检查其触发描述。skill 迁移本身不承担隔离功能。

## 已核实的执行链路

- `room-service.ts` 的本机及远端执行流程把 `pathJail: cwd` 传给 `SessionManager`；隔离必须部署在实际执行任务的成员电脑上。
- `session-manager.ts` 的 `buildOptions()` 配置 SDK 工具和 hook。`pathJailViolation()` 检查显式路径和命令文本，不检查脚本运行期间的文件访问；路径检查也没有解析符号链接或 Windows junction。
- SDK 默认启动本机 Claude Code；群聊已传入 `sandbox`，尚未接入 `spawnClaudeCodeProcess`。实测 vendor 执行器版本为 **2.1.220**，已安装 SDK 为 **0.3.220**。
- 会话加载用户、项目、本地设置以及配置的插件和 MCP；`cpa-supervisor.ts` 的 `buildProcessEnv()` 继承主进程环境。只隔离 Bash 不能自动覆盖所有这些入口。
- 本地 SDK 类型暴露 `sandbox.failIfUnavailable`、`allowUnsandboxedCommands`、文件系统策略，以及自定义 `spawnClaudeCodeProcess` 接口。类型中有原生 Windows 的说明，但这不能证明当前打包执行器已具备可用的 Windows 隔离。

## 后续可选平台（当前暂缓自建隔离）

官方在线文档当前说明内置 Bash 沙箱支持 macOS、Linux、WSL2，原生 Windows 不支持；内置文件工具使用独立的权限机制。沙箱不可用时默认可能退回普通执行，必须设置失败即停止。[Claude Code 沙箱文档](https://code.claude.com/docs/en/sandboxing)

| 路线 | 适用场景 | 接入判断 |
| --- | --- | --- |
| SDK 内置 Bash 沙箱 | Linux/macOS 执行节点；补上脚本间接写入限制 | 改动较小，但不是整个 Agent 的隔离，仍需收紧其他工具和配置 |
| Windows 原生受限执行器 | 保留现有 Windows Python、Node、Git 工具链 | 优先做兼容性原型；需要原生启动辅助程序、资源授权和进程生命周期管理 |
| 独立 Linux 容器或虚拟机 | 可以接受 Linux 工具链及额外运行环境 | 可把完整 Claude 进程放进隔离环境；需要目录、流式通信和模型代理适配 |

Windows 原生原型可基于 AppContainer，按能力和资源 ACL 授予工作目录访问，并验证 CLI、管道、网络代理和子进程兼容性。它不是 Electron 的一个配置开关，也不能仅靠设置 `cwd` 实现。AppContainer 提供文件、注册表和进程等资源隔离，启动时需要配置安全能力及进程属性。[AppContainer 隔离](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation)、[启动 AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)

当前先使用官方内置沙箱，不实施原生 Windows 执行器、容器或虚拟机。如后续需要完整进程隔离，再评估下述方案。不要把普通 WSL2 shell 本身当成隔离：仍需限制宿主盘挂载、Windows 程序互操作和宿主服务访问。

## 后续完整隔离的接入方案（暂缓）

以下是根据当前代码提出的设计，尚未经实际隔离环境验证。

1. **增加统一执行环境接口。** 在 `SessionManager.buildOptions()` 处接入环境准备、能力检测、启动、停止和资源清理。SDK 的 `spawnClaudeCodeProcess` 可作为完整 CLI 隔离的接口。UI 与审批留在桌面主进程。不可用时停止群聊命令执行，不能回退到普通本机启动。
2. **把边界覆盖到整个进程树。** CLI、脚本、孙进程和后台任务都必须继承限制；中止任务时清理整个进程树。工作区之外只提供明确的只读运行库及独立临时目录，不映射用户主目录、其他项目或宿主磁盘根目录。隔离内的临时写入与宿主工作区之外的写入应明确区分。
3. **拆开数据目录与控制配置。** 工作区内可修改的 `.claude` 配置、插件、hook、可执行脚本不能在之后被宿主直接加载执行。群聊使用应用生成的受控设置和独立会话目录；普通个人会话保持现有行为。内置沙箱方案也必须防止其他设置合并后增加写目录、关闭隔离或排除命令。
4. **收紧宿主工具桥接。** 自定义 CLI 启动不会隔离 Electron 内的 SDK MCP 回调。群聊只暴露逐项审核过的工具；本地 stdio MCP 放入同一边界，宿主回调不能成为任意文件或命令代理。Mod/扩展的宿主执行需要单独划定信任范围；如果也接受不可信代码，必须迁入受限进程。
5. **适配目录与回传。** 原生隔离需要核实工作区授权及重解析点行为；容器/虚拟机需要将宿主 `D:\\...` 映射为来宾工作路径。附件、hook 输入、差异预览、文件回滚和会话恢复都要使用同一映射。宿主处理回传路径时再次校验，不直接相信来宾返回的绝对路径；授权范围变化后重建执行环境。
6. **单独设计模型联网。** 当前 CPA 在宿主回环地址，隔离环境内的 `127.0.0.1` 未必指向它。使用只允许模型请求的窄接口代理和短期会话凭证，停止继承整个宿主环境；不要开放通用宿主命令接口、Docker 管理 socket 或任意本机网络端口。

容器/虚拟机方案可按官方部署文档采用最小目录映射、非特权运行及边界外凭证代理。具体挂载与权限仍需结合本项目验证。[Agent SDK 安全部署](https://code.claude.com/docs/en/agent-sdk/secure-deployment)

## 后续完整隔离的验收要求

测试在专用临时测试根目录内创建“工作区”和“外部哨兵目录”，不触碰真实个人文件。以下均需在实际执行器上运行，不能只验证 hook 返回值：

- 工作区内正常读写、运行 Python/Node、构建可以成功；只读轮次不能写。
- 工作区内的脚本尝试访问外部哨兵目录，包含动态拼接路径、子进程、后台执行，均被系统阻止。
- 符号链接、junction、重命名替换及跨盘路径不能突破文件边界；包含内置文件工具。
- 修改项目设置、请求禁用沙箱、通过 MCP 或扩展间接调用，不扩大宿主权限。
- 依赖缺失、隔离初始化失败、恢复旧会话、切换工作区均不回退为无限制执行。
- 任务中止后无遗留可写后台进程；正常差异预览、附件读取及回滚仍然有效。

原型通过后，再确定正式后端并接入群聊入口。当前路径 hook 可继续提供提前拒绝和清晰错误，但不承担操作系统隔离的保证。
