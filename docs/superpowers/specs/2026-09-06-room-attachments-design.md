# 群聊附件与协作界面：已确认设计

2026-09-06 用户以“继续”批准上一轮原型与本批实现。仅改群聊，保留已有未提交修改；不提交、不部署、不改全局样式。

## 本批边界

1. 附件必须传递实际字节，不能把另一台电脑的路径当作文件。图片、文本和 PDF 可交给 Agent，其他文件可下载但不得伪装为文本输入。
2. 群聊采用已讨论的 B 布局：人类柔和气泡、Agent 无外层气泡，右侧任务 / 成员 / 活动切换，小窗口可收起。任务审批、停止权限、显式 @ 和个人授权规则不变。
3. 不在本批实现常驻房间服务或全局账号；不出现已经托管、云历史或跨设备账号可用的虚假界面。

## 附件契约

- `RoomAttachmentRef` 只有 id、name、size、mimeType、kind、sha256，不包含路径或文件内容。
- 使用独立群聊缓存，按房间隔离、随机附件 id 命名。导入复制实际文件并计算摘要；网络接收核对字节数与 SHA-256 后才原子落盘。路径完全由本机生成。
- 初始资源限制：每条最多 5 个文件、单文件最多 10 MiB、合计最多 25 MiB；图像 / 文本送模型最多 5 MiB，PDF 最多 10 MiB。未知二进制只下载。缓存有总量上限，失败明确报告，不静默丢弃已发布附件。
- 通过已有房间连接按需拉取固定大小的数据块。请求 / 响应均绑定房间、连接身份、随机请求 id 和偏移；限制并发、超时与发送速率。复用原有加密通道，不发送本地绝对路径。
- 带附件的消息等待房主接收校验完成后发布及确认。传输在消息队列之外完成，避免阻塞普通聊天；失败保留草稿。消息请求 id 用于重试去重，成功消息记录该 id。
- 审查补充：发送回执独立于 400 条显示历史持久化，采用带时间的随机 id，最多保留 8192 条、重试窗口 7 天。清理时持久化时间下界，过期 / 被清理 id 明确拒绝，绝不视为新任务；不自动重置旧草稿的 id。设备时钟超前超过 5 分钟时提示同步时间。
- 撤回后的旧 metadata 不代表发送方拥有文件：接收群成员附件时仍拉取其实际字节。未知发送结果复用不可变副本；明确未发布的失败批次回收缓存。缓存删除在锁内再次检查在用引用，不删除原文件和已发布附件。
- 群成员只能下载仍可见且未撤回消息的附件；Agent 执行端只能拉取已授权任务引用的内容。不能通过任意缓存 id 读取他人文件。
- Agent 在附件完整、可读、类型支持时才启动。取消任务会终止等待；不把读取错误当作成功或自动启动缺失输入的任务。
- 本开发版本无需兼容旧版，因此应用房间协议升级为 3；加密及握手封装版本仍为 1。

## UI

- 复用现有群聊状态和控制，不改变其他页面、全局 CSS 或 Mod 运行逻辑。
- 默认显示任务侧栏，审批置顶；成员与活动在独立页签内。小窗口侧栏可收起，键盘和屏幕阅读器可操作。
- 附件卡片明确区分未下载、处理中、可预览 / 保存、失败；只显示实际状态，不显示“AI 已读”。
- 粘贴截图复用已有安全剪贴板图片保存 IPC，再按普通附件发送。
- ctx 沿用实际数据及压缩阈值；压缩后未有新数据时不得伪造 0%。
