# 群聊体验第一批实施规格

依据前述 B「协作群聊」原型、用户逐项确认及“开始做吧”指令实施。

## 范围

本批落地群聊消息视觉和多 Agent 调度。保留上一批 Mod 参与门禁；不改全局样式、账号、传输拓扑、群权限、模型共享、工作区授权或旧 Mod 运行位置。跨机附件内容传输、常驻群服务、全局账号和完整任务历史各自属于独立阶段，本批不宣称已完成。

## 消息与执行

人类发言使用柔和气泡：自己的靠右，其他人的靠左。向 Agent 发出的指令依然是人类消息，不能因目标席位是 Agent 而变成 Agent 样式。Agent 回答与执行过程不使用聊天气泡，保留头像、名称、Markdown、代码和引用。实时执行按席位/turnId 分开显示。

发送一条包含多个明确 @Agent 的消息，时间线只记录一次用户发言，处理端并行启动每个目标一次。人类提及不启动 Agent，也不遮蔽同条消息中的 Agent；重复提及去重，长名称优先匹配，邮件地址与名称前缀不应误触发。未明确提及任何席位时，保留当前选中 Agent 的发送方式；只 @ 人类时从自己的席位发言。

同一 Agent 的新请求不能覆盖正在运行或等待授权的任务。忙碌目标明确报告未启动，其他空闲目标继续执行；不自动中断或重试。每个目标沿用已有文件审批、远程执行节点和模型权限。`/stop` 可停止消息里明确提及的多个 Agent，否则沿用当前选中 Agent。

## 交互与兼容

保留当前 @ 候选框的鼠标与键盘操作，不添加发送对象下拉框。沿用引用、撤回、消息通知和附件选择入口。ctx 显示与 75% 自动压缩逻辑不改；已有功能的兼容性通过回归测试覆盖。

不以“运行中”推断任务成功，不编造持久任务列表或跨机附件可用状态。原型中的完整任务历史和项目结果归档不在这一批实现。

## 验证

真实 RoomService + 本地 WebSocket 验证宿主和成员的多目标发送、一次时间线写入、同席位防重入、失败隔离；模型执行只在 SDK 边界使用替身。静态 React 渲染验证消息类型、无气泡 Agent 和独立实时状态。最终运行桌面测试、共享协议测试、类型检查和构建；核对既有 styles.css 哈希不变。
