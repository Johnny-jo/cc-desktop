# TaskList 与 SubAgent 生命周期改进

日期：2026-09-07。状态：方向已获用户认可，具体交互待审查。

## 目标与范围

改进主聊天及复用 ChatPanel 的独立会话窗口，让用户区分任务完成、计划关闭，以及代理成功、失败、停止。延续现有输入框上方按钮和上拉面板。群聊跨设备同步不包含在本次范围内；当前状态属于桌面会话。

## 方案比较

1. 仅改计数文案：改动小，但不能表达计划关闭。
2. 推荐：保留 SDK 任务状态，增加应用侧计划关闭信息，改善代理状态汇总。兼容现有事件与历史记录。
3. 引入计划版本、独立任务终止状态和代理控制：可管理多份计划，但需要新的身份、归档及执行协议，本次不采用。

## TaskList 行为

当前会话的全部任务构成一份清单，不按每轮对话生成计划。任务仍按 `(scope, id)` 关联，状态保持 pending、in_progress、completed，允许后续成功更新重新打开已完成任务。

按钮展示完成数量和清单状态：有进行中任务时为「TaskList 1/5 · 进行中」；只有待开始任务时为「TaskList 0/5 · 待开始」；部分完成、其余待开始时为「TaskList 2/5 · 待继续」；全部完成时为「TaskList 5/5 · 全部完成」。全部完成不会自动关闭计划。

面板增加「关闭计划」和关闭后的「重新打开」。关闭属于用户对清单的管理操作，不修改任务状态、不停止模型或后台代理。按钮旁固定说明「关闭仅标记计划结束，执行中的任务仍会继续」。允许在存在未完成任务时关闭，显示「已关闭 · 2/5 完成，3 项未完成」，不将未完成任务算作成功。

关闭后清单仍可展开，仍接受真实工具更新，但不会自动变回打开状态。关闭后如清单内容实质变化，显示「关闭后有更新」；用户重新打开后清除该提示。重复事件及仅代理进度变化不触发提示。关闭信息记录的是用户意图，清单展示的是最新事实，二者独立。

无任务且从未关闭时不显示 TaskList；关闭后的清单即使收到空列表，仍显示「已关闭 · 无任务」，保留重新打开入口。重新打开后若仍无任务，入口隐藏。

## SubAgent 行为

运行数量只计算 running；已结束数量计算 completed、failed、stopped。paused、unknown 不计入已结束。保留现有终止态防回退逻辑。

紧凑按钮展示「SubAgent 0 运行中 · 1/1 已结束」。存在 failed 时补充「1 失败」；存在 stopped 时补充「1 已停止」。停止可能是主动操作，不一律标成失败。paused、unknown 也必须在紧凑区可见，分别显示「1 已暂停」「1 状态未知」，窄窗口允许换行，不能隐去这些状态。

面板顶部和每行保留成功、失败、停止、暂停、未知的明确文字与结果摘要。重启恢复的原运行中或暂停代理继续按现有逻辑标为未知，不能推断为成功。本次不增加停止或恢复执行按钮。

## 状态、持久化与数据流

SDK 任务事件继续经归一化、进度合并、SessionManager 持久化并广播到界面。仅成功完成的任务工具调用改变清单，保留作用域隔离、重复事件过滤及完整记录重建。

用户关闭信息作为可选的会话摘要字段 `taskPlan` 保存，避免任务进度重建覆盖用户意图。字段包含 `closedAt` 和 `changedSinceClose`；缺失表示打开。关闭时设时间并清除更新提示，重新打开时移除此字段。

主进程比较任务内容的实质变化（含新增、删除、状态、标题、描述、负责人、作用域和活动描述），关闭期间发生变化时设置 changedSinceClose。保持共享的纯比较函数，不依赖渲染顺序或数组引用判断。旧会话没有该字段时兼容为打开。

新增类型化会话 IPC 来关闭或重新打开计划，由主进程校验会话存在并保存、广播，主窗口与独立窗口使用同一状态。界面等待成功响应；操作期间禁用重复点击，失败时保持原状态并显示错误。按主进程接收顺序处理并发关闭和任务更新。

关闭信息随会话摘要持久化；压缩不清除它。显式回退聊天记录时清除关闭信息，以免将后来的关闭意图套用到较早的任务版本。归档加载先恢复该字段，再对真实后续任务变化计算更新提示；加载和重复广播本身不标为更新。

## 验证与验收

- 任务计数：待开始、进行中、全部完成均准确；关闭不改变任务状态或终止执行。
- 关闭后任务成功更新、删除或列表替换能显示新事实和更新提示；重复、失败事件和代理心跳不误触发。
- 关闭与重新打开持久化，主窗口与独立窗口一致；旧档案默认打开，压缩保留，回退清除。
- 代理成功、失败、停止都计入已结束，暂停和未知不计入；终止态不被迟到事件复活。
- 组件覆盖空清单、窄窗口、关闭后更新提示、操作失败、键盘关闭和焦点恢复；中文与英文均可读。
- 运行受影响的状态、归一化、归档、IPC 和组件测试，以及项目类型检查。用实际渲染确认按钮换行与面板操作区域；不可用时明确说明验收限制。

## 后续影响

未来真正的多计划管理需要稳定 planId 和明确的任务归属，不能用时间戳或对话轮次猜测。跨设备共享关闭状态需要服务端成员身份、版本和冲突规则；本次本机会话字段不能直接宣称已经支持跨设备同步。
