# 主对话执行过程极简布局设计

**日期：** 2026-09-04  
**状态：** 第二轮视觉方案已确认，待书面规格复核
**范围：** Electron 桌面端主对话区；仅调整消息组织、过程展示与样式，不改变 Agent 事件协议和持久化格式

## 1. 背景与目标

当前主对话将思考内容、每次工具调用、最终回答和文件变更分别渲染为独立块。长任务会连续出现多个边框卡片，视觉层级相近，导致最终回答被过程信息淹没。

本次设计将同一轮 AI 回复中的思考和工具调用聚合为一个“执行过程”，让用户在运行时仍能看到进度，在完成后优先阅读最终回答。

成功标准：

1. 一轮任务只有一个执行过程入口，不再平铺多个工具卡片。
2. 运行时自动展开当前过程；完成后自动折叠为一行摘要。
3. 执行过程不使用边框卡片或大面积底色。
4. 只有当前步骤显示 loading 动画；已执行步骤为灰色；当前和未执行步骤使用主文字色。
5. 最终回答是完成态的视觉主体。
6. 文件变更在最终回答下方使用 Codex 式结果卡，保留文件明细与整轮撤销，不提供审核按钮。
7. 用户消息与其后的 AI 回合间距约为 32px，AI 回合内部保持紧凑。

## 2. 信息结构

每个用户消息开启一个回合。该回合后续出现的思考、工具调用、AI 正文、用量和文件变更按以下层级展示：

```text
用户消息
└─ AI 回合
   ├─ 执行过程（思考 + 工具调用，严格按事件顺序聚合）
   ├─ 最终回答
   ├─ 文件变更入口（仅在本轮有变更时出现）
   └─ 用量信息（沿用当前弱化展示）
```

执行过程属于 AI 回合的辅助信息，不与最终回答争夺同级视觉权重。其内部只有一条时间主轴，思考和工具调用均为同级时间事件：谁先发生谁在前，不推断某段思考属于哪个工具，也不重新排列。文件变更是结果而非过程，因此不收进执行过程。

## 3. 执行过程交互

### 3.1 运行中

- 标题为“正在执行”。
- 自动展开，不要求用户手动打开。
- 标题行显示当前步骤摘要和进度，例如“整理工具调用与状态 · 2 / 4”。
- 标题、汇总信息和 AI 正文使用相同的 16px 基准字号；状态文字可以略小。
- 整组展开图标位于“思考 N 次 · 调用 N 个工具 · 用时 N”汇总之后，完成/失败状态仍靠右。
- 已执行步骤只显示灰色文字，不显示勾选、圆点或其他完成图标。
- 当前步骤前显示 12px 左右的旋转 loading 图标，文字使用主文字色。
- 尚未执行步骤不显示图标，文字使用主文字色。
- 每个思考事件默认显示为一行较浅的斜体文字，超出宽度显示省略号；折叠图标紧跟在该行末尾，点击整行展开全文。
- 工具调用使用更明确的字重展示“工具名 + 摘要 + 耗时”，与思考事件形成类型层级，但二者顺序严格服从原始事件时间线。
- 用户可以手动折叠；出现新的当前步骤时不强制抢回展开状态，避免与用户操作争夺控制权。

### 3.2 完成

- 自动折叠为一行“执行过程”。
- 摘要格式为“思考 {n} 次 · 调用 {n} 个工具 · 用时 {duration}”。没有某类数据时省略对应片段，不显示零值占位。
- 末尾显示“完成”，不再显示 loading。
- 用户仍可手动展开查看步骤和工具详情。
- 展开后的全部步骤均为灰色，因为它们都已执行。
- 完成态的思考仍默认单行截断，仅用户主动点击的单条思考展开。

### 3.3 失败或中止

- 失败时停止 loading，标题保持“执行过程”，末尾状态显示“失败”。
- 出错步骤使用危险色文字，但不增加高权重背景或边框。
- 中止时显示“已停止”，保留已经产生的步骤和结果。
- 失败和中止状态默认保持展开，便于用户直接看到最后一步；用户可手动折叠。

## 4. 视觉规则

采用“正文状态轨道”而非卡片：

- 执行过程容器无外边框、无整体底色、无阴影。
- 折叠标题与最终回答左侧对齐，保持同一阅读轴。
- 展开内容仅使用一条细竖线表示从属关系。
- “执行过程”和其汇总信息使用与 AI 正文一致的基准字号，标题用字重而不是字号建立层级。
- 整组展开图标放在汇总信息之后；单条思考的展开图标放在截断文字之后。
- 不使用勾选、空心圆、步骤编号或工具类型彩色徽章。
- loading 是运行态唯一的动态强调；动画尊重 `prefers-reduced-motion`，减少动态时改为静态半圆图标。
- 已执行步骤使用 `--text-faint`；当前和未执行步骤使用 `--text`；思考预览使用 `--text-faint`。
- 浅色主题中的主文字接近黑色；深色主题使用对应的高对比主文字，不强制显示黑色。
- 可点击标题保留完整键盘 focus 样式，整行点击区域至少 30px 高。
- 用户消息与下一个 AI 回合之间使用 32px 左右的外间距；执行过程、AI 正文和文件结果之间使用 12–20px 的内部节奏。

## 5. 组件边界

### 5.1 `MessageList`

负责把扁平的 `ChatItem[]` 按用户回合分组，并保持分页、滚动锚点、跳转到底部和会话导航逻辑不变。它不负责渲染单个工具的细节。

建议在渲染层派生 `ConversationTurn[]`，不修改 store 和磁盘中的原始消息结构：

```ts
type ConversationTurn = {
  id: string;
  user?: TextChatItem;
  activity: ActivityEntry[];
  answer?: TextChatItem;
  changes?: ChangesChatItem;
  usage?: UsageChatItem;
};
```

### 5.2 `ActivityGroup`

负责聚合过程标题、自动展开策略、摘要统计和事件时间线。输入只包含当前回合的思考与工具事件，不读取全局 store。

```ts
type ActivityEntry =
  | { kind: "thinking"; text: string; active: boolean }
  | { kind: "tool"; tool: ToolCardState };
```

### 5.3 `ActivityEvent`

按原始数组顺序渲染单个思考或工具事件：

- 思考事件：默认一行截断，点击整行独立展开/折叠全文。
- 工具事件：显示工具名、摘要和耗时；结果预览和 Todo 列表仍作为该工具的二级详情。
- 组件不做“思考归属工具”的语义推断，也不按类型重新分组。

### 5.4 `TurnChangesCard`

采用 Codex 式结果卡：

- 头部显示文件数量、总增加/删除行数和“撤销”。
- 不显示“审核”按钮。
- 下方默认显示前三个文件及各自增删统计；剩余文件通过“再显示 N 个文件”展开。
- 点击文件继续使用现有打开文件能力；点击“撤销”调用现有 `restoreAllChanges(sessionId)`，恢复本轮可恢复的全部文件。
- 撤销期间按钮显示进行中并禁用；结束后展示成功数量和失败文件，行为与右侧 Changes 面板一致。

## 6. 数据与状态流转

1. transcript reducer 继续生成当前 `ChatItem[]`，不改变事件归一化和持久化。
2. `MessageList` 根据消息顺序将用户消息之后、下一条用户消息之前的内容派生为一个 AI 回合。
3. 同一回合的 `thinkingText` 和 `tool` 项按原始索引进入 `ActivityGroup`；AI 正文、changes 和 usage 保持各自结果位置。
4. 任一工具为 `running` 或 AI 仍处于 thinking streaming 时，回合过程状态为运行中。
5. 回合结束且没有失败工具时，状态为完成；存在 error 工具时，状态为失败；会话被主动停止时为已停止。
6. 聚合仅发生在展示层，绝不按事件类型排序。滚动定位继续使用原始 item id；执行过程容器需携带内部首项 id，并允许根据任一子项 id 定位到该回合。
7. 文件卡的增删合计由本轮 `files` 派生，撤销复用已有 IPC，不新增文件写入协议。

## 7. 展开状态规则

组件保存两个状态：系统建议状态和用户覆盖状态。

- 新回合运行开始：默认展开。
- 用户在运行时手动折叠：记录用户覆盖，后续工具进度更新不重新展开。
- 回合由运行转为完成：清除运行时覆盖并自动折叠。
- 用户在完成后展开：后续父组件重渲染不自动关闭。
- 切换会话或回合 id 变化：重新按该回合当前状态初始化。

这样既满足运行中自动可见、完成后自动降噪，也避免当前 `useEffect` 在每次状态变化时覆盖用户手动选择。

## 8. 可访问性

- 执行过程标题使用原生 `button`，提供 `aria-expanded` 和关联内容的 `aria-controls`。
- 每条思考使用独立按钮，提供 `aria-expanded`，截断仅是视觉表现，辅助技术仍可取得完整文本。
- loading 图标为装饰元素；当前步骤通过可见文字“进行中”表达状态，不依赖动画或颜色。
- 完成、失败和停止状态均有可见文字。
- 颜色对比沿用现有主题令牌；灰色已执行文字仍需达到普通辅助文字的可读对比度。
- 键盘可展开和折叠执行过程，并可继续操作工具详情与文件变更入口。

## 9. 响应式与长内容

- 执行过程宽度跟随聊天正文，不超过现有 `--chat-max`。
- 标题摘要单行截断，完整内容通过展开后的步骤呈现。
- 单条思考默认单行截断，展开后自然换行；长文本达到最大高度后内部滚动。
- 工具结果预览保留最大高度和内部滚动，避免单项撑满对话区。
- 窄窗口下隐藏耗时和总进度中的次要信息，但保留当前步骤、loading 和状态文字。
- 长思考文本限制可视高度，内部滚动；完成态默认折叠。

## 10. 测试与验收

### 10.1 单元测试

- 扁平消息正确分组成多个用户回合。
- 思考与多个工具被聚合到同一 `ActivityGroup`。
- 思考与工具保持输入数组的严格顺序，不发生按类型重排。
- 无思考、无工具的普通回答不渲染执行过程。
- 摘要正确省略不存在的统计项。
- running、done、error、stopped 状态计算正确。

### 10.2 组件测试

- 运行中默认展开，完成后自动折叠。
- 用户手动折叠运行中过程后，进度更新不重新展开。
- 完成后手动展开，普通重渲染不关闭。
- 只有当前步骤存在 loading；完成项和等待项没有前置图标。
- 单条思考默认截断，点击整行可独立展开，再次点击可收起。
- 执行过程的整组折叠图标位于汇总文字之后。
- 文件卡默认显示前三项，“再显示 N 个文件”可展开和收起剩余项。
- 文件卡撤销调用整轮恢复能力并正确展示忙碌、成功和部分失败状态。
- `aria-expanded`、键盘操作和 reduced-motion 样式有效。

### 10.3 回归检查

- 历史分页和加载新消息时不改变滚动位置。
- 对话导航仍能定位用户消息和 AI 回合。
- streaming 自动滚动、跳到底部、rewind、附件和 Markdown 渲染保持原行为。
- 深色与浅色主题下已执行、当前、未执行三种文字层级均清晰。
- 用户消息与 AI 回合的外间距增加，但同一 AI 回合内部没有被等量拉散。

## 11. 非目标

- 不修改 Agent SDK、IPC 事件、transcript reducer 或磁盘数据格式。
- 不增加全局“始终展开过程”设置。
- 不重做右侧 Changes 面板。
- 不增加文件审核、接受/拒绝变更或 hunk 级操作。
- 不在主对话中展示完整日志、原始 JSON 或所有工具输入参数。
- 不改变 Composer、会话侧栏和顶部栏的功能。
