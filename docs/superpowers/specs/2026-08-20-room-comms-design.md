## 1. 一句话

> 房主是权威计算节点，必须见明文；客人只连房主。`RoomFrame` 不动。帧下垫应用层 AEAD 信道与设备身份。传输是哑管道：局域网 WS、公网 WSS、Cloudflare Tunnel 三选一可达。密码不进邀请码。离线即错过，重连拉快照。

规模：2–100 人，一种拓扑通吃。本期不立项 WebRTC / TURN / MLS / Dead Drop。

## 2. 产品前提（不可再议）

| 前提 | 含义 |
|---|---|
| 房主权威 | Agent、文件系统、CPA、`room.chat.in`、玩法 reduce 只在房主进程；客人不执行 kernel |
| 房主是端点 | 房主见明文。被攻破 = 全群明文。这是产品形态，不是缺陷 |
| 星型 | 客人永不互连。踢人 = 断该信道 + 废弃会话密钥 + 指纹进黑名单 |
| ≤100 人 | 草案按规模分档（mesh / SFU / MLS / 群钥）整节删除 |
| 通道可替换 | 加密与可靠性不绑任何一种传输 |

本协议服务 **Agent 协作房间**，不是对等密信 IM。

## 3. 威胁模型

| 威胁 | 承诺 |
|---|---|
| 被动窃听（LAN 嗅探、隧道运营商、证书路径上的中间盒） | 应用层 AEAD，中间方只见密文 |
| 主动中间人 | 邀请码带房主设备指纹；TOFU；指纹变化告警并重新审批 |
| 平台拒绝服务 | CF Tunnel / 公网不可用时，局域网房仍可用；协议不依赖某一隧道存在 |
| 元数据观察 | 运营商可见「谁在何时连了哪个域名/IP」，不可见帧内容。接受此代价 |
| 设备丢失 / 被盗 | 房主吊销该设备指纹；被踢设备持旧邀请码无法重入 |
| 邀请码泄露 | 无密码仍不能完成握手；新设备默认需房主审批 |
| 房主失陷 | **不防护**。明文在房主是内禀属性 |

删除「从密钥到字节不信任任何第三方」。诚实表述：

**身份去中心，可达性机会主义，机密性对中继/隧道端到端。房主除外。**

## 4. 协议栈

```
┌─────────────────────────────────────────────────────────┐
│  应用协议    RoomFrame（现有 JSON 帧，v 字段独立演进）     │
│              hello / welcome / chat / seat / mod / kernel │
├─────────────────────────────────────────────────────────┤
│  会话可靠    msg_id 去重 · 累积 ACK · 水位线 · 整信封重传   │
│              重连拉房主快照 + 最近 N 条（离线即错过）       │
├─────────────────────────────────────────────────────────┤
│  加密信道    设备钥握手 → 会话密钥；每帧 AEAD 信封          │
│              （ChaCha20-Poly1305 或 AES-256-GCM）         │
├─────────────────────────────────────────────────────────┤
│  传输（哑管道，可替换）                                     │
│    T0  LAN WS          现有，默认端口 18765                 │
│    T1  公网 WSS        房主有入向（IPv6 / 端口转发）         │
│    T2  CF Tunnel       房主无入向；wss:// 隧道域名           │
│    （远期）WebRTC DC   既无入向又不用隧道时再立项            │
└─────────────────────────────────────────────────────────┘
```

TLS / 未来的 DTLS 是纵深防御：有更好，没有不影响机密性。CF 边缘终止 TLS 时，应用层 AEAD 仍然包着 `RoomFrame`。

术语固定三词，禁止都叫「会话」：

| 词 | 指什么 |
|---|---|
| Conversation | 房间消息会话（`roomId` + 时间线） |
| Connection | 一条客人↔房主逻辑信道（握手后的会话密钥绑定在这里） |
| Path | 底下那条 TCP/WSS/隧道五元组 |

## 5. 拓扑与数据流

```
客人 A ──AEAD──┐
客人 B ──AEAD──┼── 房主（明文：时间线 / Agent / hook / 权限）
客人 C ──AEAD──┘         │
                         ├── T0 本机 listen WS
                         ├── T1 公网 :443/:18765 WSS
                         └── T2 cloudflared → wss://room.<域名>
```

- 一条群消息 = 房主解密 → 权威状态机处理 → 在其余 n−1 条信道上各自加密转发。
- **没有群密钥。** MLS / Sender Keys / mesh / SFU / 超级节点选举全部移出本项目。
- 同步权威 = 房主快照 + 按发送设备的水位线。Lamport 若保留，只用于 UI 排序。
- Agent 流式 token 是持续扇出；S1 先正确送达，S2 再做写合并与背压（见 §12）。

## 6. 身份、加密、邀请、入场

### 6.1 密钥

v1 每端一对 **设备密钥（X25519）**。首次连接做 ECDH，派生该 Connection 的会话密钥；每 `RoomFrame` 走 AEAD。

- 邀请码携带**房主设备指纹**（公钥哈希）。客人 TOFU 记录，之后变更必须告警。
- 完整 X3DH、长期身份钥签发/吊销网、助记词：**v1 不做**。若将来做，IK 绑定设备钥，长期身份钥只签发/吊销，备份密钥 HKDF 分域，禁止与签名/握手复用。
- 踢人 / 设备吊销：废弃该 Connection 会话密钥 + 断连 + 指纹进房间黑名单。重入 = 新握手，房主持拒绝权。

### 6.2 邀请码 `CDR2.`

密码**不得**出现在邀请码里（现状 `CDR1.` 把口令明文嵌进码内，XOR 换 KDF 也堵不住）。

`CDR2.` 只带：

- 地址：LAN `host:port` 列表，和/或 `wss://` 公网/隧道 URL
- 房主设备指纹
- 房间名
- 可选 `modChecksum`

旧 `CDR1.`：v1 内只读解码，提示「旧版本生成，安全性不足，请让房主重新生成」。禁止继续用旧码建连。

### 6.3 密码认证

握手用 **PAKE（首选 CPace）**。最低可接受降级：HMAC 挑战-响应。禁止传输密码，禁止可离线爆破的口令等价物上线。

密码错误 = 握手失败，与网络错误可区分，但不泄露成员列表、房间状态等额外信息。

**未通过密码认证前不分配**席位、mod 状态、会话对象。

LAN 房创建时可勾选「跳过加密握手」（便利项）。**默认开启加密。** 该选择写入 `RoomSnapshot`，全体可见，禁止静默降级。公网 / 隧道房不允许跳过。

### 6.4 入场审批

- 新设备首次入房：房主看到指纹 + 名称，**默认审批**。现有 `autoApprove` 语义保留：开则自动放行，仍记指纹。
- 指纹变化：告警房主与该用户，需重新审批。
- 黑名单指纹持旧邀请码重连 → 拒绝。

## 7. 传输三件套

| 代号 | 何时用 | 谁暴露入向 | 中间方 |
|---|---|---|---|
| T0 LAN WS | 同一局域网 | 房主 LAN IP:18765 | 无（链路仍走 AEAD） |
| T1 公网 WSS | 房主有公网入向 | 房主 IPv6 或端口转发 | 路径上的 TLS 终结者（纵深） |
| T2 CF Tunnel | 房主无入向 | 作者 named tunnel / 房主自建隧道 | Cloudflare（只见密文） |

选路对客人：邀请码里的地址按「能连上的先用」尝试（LAN 候选与 `wss://` 可并行短超时）。不自研 ICE。

### 7.1 Cloudflare Tunnel 定位

- 作者提供的**小圈子默认入口**，不是面向全体分发用户的公共基础设施承诺。
- named tunnel 挂自有域名（如 `room.<域名>`）。`cloudflared` 随软件内置；房主「创建公网房」一键拉起。
- 房主与客人只见域名，不接触 CF 账号。配合 AEAD，账号持有者也不可见内容。
- **单点**：隧道挂了，公网房不可用；局域网房不受影响。
- 协议与代码不依赖该隧道：T2 只是一种 Path 实现，删掉不影响正确性。
- 进阶：房主用自己的 CF 账号 + 域名；邀请码兼容任意 `wss://`。

### 7.2 明确不做（本期）

- WebRTC DataChannel / ICE / STUN / TURN（Node 无原生 WebRTC，且星型下打洞主要服务「房主无入向」——T2 已覆盖）
- TCP 打洞、TLS-443 伪装
- Git / Gist / 公共 MQTT 当消息后端、预钥目录、控制面
- 跨 Path 半包续传；连接迁移 &lt; 1s 的承诺

WebRTC 的立项触发：**相当数量房主既无公网入向、又不愿用隧道**。届时须先补：信令通道、ICE restart 来源、Node 侧选型 spike、国内 STUN/TURN 部署主体。

## 8. 会话可靠与离线

- 每帧 `msg_id`（发送方设备 + 单调序号）去重；累积 ACK。
- 未 ACK 的**整信封**换 Path 重发。禁止一条 `RoomFrame` 拆开走两条 Path。
- 大文件另走分片 + 哈希树，不与聊天帧共用续传。
- **离线即错过。** 不保证离线队列。重连：认证通过后拉房主快照 + 最近 N 条（N 在实现规格里钉，建议时间线已有窗口，不另造邮箱）。
- 不做信封级 TTL（墙钟与逻辑钟混用已否决）。若将来做离线附件，TTL 以发送方墙钟为准、偏差 ±10 分钟。

房主进程重启 → 房间 ended。与现状一致，S1 不承诺房主崩溃后续摊。

## 9. 滥用防护（公网 Day-1）

局域网假设失效后攻击面质变，与加密同一期做：

- 按帧类型的大小上限（`mod.bundle` 已有 `MOD_BUNDLE_MAX_BYTES`；聊天/快照/握手另限）
- 每连接速率限制 + **单客人**令牌桶
- 握手超时、半开连接清理
- 伪造 / 乱序 `roomId`、`seq`、未知帧类型：按版本规则忽略或明确失败，并计入速率限制
- 重连风暴：房主侧重连令牌桶 + 快照缓存（规模到几十人时会痛，S1 先有桶，S2 再优化差量）

## 10. 版本与观测（Day-1）

- `RoomFrame.v` 继续作为应用协议版本；AEAD 信封自带传输版本。二者独立演进。
- 旧端遇未知应用帧类型：可忽略或明确失败，**禁止静默损坏房间状态**。
- 观测：建连成功率、各 Path 占比（T0 / T1 / T2）、握手失败原因（密码 / 指纹 / 审批 / 超时）、重连耗时、扇出字节。没有数据不调超时。

## 11. 与现行代码的关系

| 现状 | S1 怎么动 |
|---|---|
| `RoomFrame` JSON、房主 `WebSocketServer`、席位/玩法/kernel | **应用协议不动**；传输与加密垫在下面 |
| `CDR1.` XOR 邀请码 | 废止为只读提示；新发 `CDR2.` |
| 房间密码比明文 | PAKE；密码离开邀请码 |
| `userId` 随机 UUID | 保留作房间内显示 ID；另增设备指纹 |
| 客人重连 3 次 × 30s | 改为认证后拉快照 + ACK/水位线 |
| 仅 LAN IPv4 候选 | 邀请码可带多 LAN IP + `wss://` |
| 无加密 | 默认 AEAD；LAN 可显式关闭 |

迁移：同一套 AEAD 代码走 T0/T1/T2，不维护「局域网明文 / 公网密文」两分支。

## 12. 阶段

| 阶段 | 谁能进房 | 做什么 | 协议是否变 |
|---|---|---|---|
| **S0 现状** | 局域网 2–6 人 | — | — |
| **S1 本期** | 公网 2–30 人为主，协议按 100 人设计 | 设备钥 + AEAD；PAKE；`CDR2.`；T0/T1/T2；审批/黑名单；滥用防护；观测与版本 | 帧下垫信道；`RoomFrame` 类型集可加握手帧，旧类型语义不变 |
| **S2** | 稳定到 100 | 扇出写合并、快照差量、旁观者只读流、重连风暴、房主上行规划 | **不变** |
| **S3a**（若需要） | 超 100 围观 | 只读扇出中继，中继只见 AEAD 密文 | **不变** |
| **S3b** | — | MLS / 对等 E2E 大群 | 另一个产品，不做 |

S1→S2→S3a 是斜坡：不加密码学、不换拓扑。S1 **无立项前置**（原 TURN 预算阻塞已解除）。

S1 不把 100 人扇出性能当验收线；验收是：公网客人能进、中间方只见密文、密码与审批成立、LAN 仍能用。

## 13. 实现时才钉的细节（不阻塞本架构）

这些不影响分层，留给实现规格 / spike：

1. AEAD 算法二选一（ChaCha20-Poly1305 vs AES-256-GCM）与 nonce 构造
2. 握手状态机（Noise 风格 IK/XX，或自写 ECDH + PAKE 顺序）
3. CPace 库可用性；不行则 HMAC 挑战-响应，文档标注降级
4. `cloudflared` 内置、named tunnel 凭证如何进安装包且不泄漏给客人
5. 最近 N 条的 N；快照差量格式（S1 可先全量快照）
6. 帧类型分大小上限的具体数字

## 15. 验收标准（S1 完成时）

1. 局域网客人用 `CDR2.` + 密码进入加密房，抓包看不到 `RoomFrame` 明文。
2. 公网客人仅凭 `wss://` 邀请进入同一套协议；CF 账号持有者无法从隧道流量还原聊天。
3. 错误密码拿不到成员列表；未审批设备进不了默认审批房。
4. 被踢设备换网络重连仍被拒。
5. 房主关掉隧道后局域网房仍在；去掉 T2 代码路径不影响 T0 正确性。
6. 旧 `CDR1.` 粘贴时只提示升级，不能当作入场凭证。
7. 观测能区分 T0/T1/T2 建连成败。
