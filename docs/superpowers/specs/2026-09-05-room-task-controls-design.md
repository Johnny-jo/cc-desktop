# 群聊有效提及与任务控制规格

依据用户在审查后的逐条确认及“开始执行吧”实施，替代第一批规格中按正文扫描提及、任何成员可停止席位、忙碌直接丢弃任务的规则。

## 范围与边界

仅修改群聊相关行为；保留人类柔和气泡、Agent 无气泡、图片文件选择、ctx 与既有 75% 压缩、Mod 可选参与、局域网及中继路径。不实现全局账号或常驻群服务器，不更改 Mod 自修改 L0～L2 的含义。不提交、推送、部署；保留原有 styles.css 内容。

## 有效提及

人类通过候选框或点击头像生成带 seatId 与正文位置的提及记录。只有正文中该位置仍为 `@名称 `（末尾普通空格）的记录才有效；手输未选择、粘贴、文件名、引用和普通 Agent 输出不会成为有效提及。编辑破坏名称或尾空格即失效。重复目标只触发一次。发送身份保持人类本人，发送对象与显示身份分离。没有有效 Agent 提及时不得因历史选中席位意外执行；单独 `/stop` 可使用明确选中的 Agent，但处理端最终按任务归属授权。

Agent 使用绑定当前群、席位与任务的结构化工具选择目标 ID，工具生成相同提及。通知人类走群内提及提醒；通知 Agent 进入待读上下文，不唤醒新任务；交办 Agent 才创建子任务。消息、引用与任务关联不依赖字符串解析。不向群外发送、不继承群主身份。

## 任务与审批

每个任务有不可由客户端伪造的 ID、原始人类发起人、目标席位、父任务、状态与读写范围。同一 Agent 串行，不同 Agent 保持并行。审批逐条展示；挂起任务显示等待确认，已批准但席位繁忙显示排队。拒绝、停止与迟到批准不能让已取消任务复活。

转交审批由原始人类发起人确认，设置也属于该成员：ask（默认逐次确认）、read-only（无修改自动、修改需批）、auto（已授权范围内自动）。逐次转交检查规则，原始发起人不变。目标成员的项目权限独立生效，禁止不能被转交批准覆盖。只读依靠执行端工具门禁，不依赖 Agent 自述；修改和无法判断副作用的工具须暂停申请写权限。继续转交限深、每条任务链限量，工具请求去重。

## 中断权限

普通成员只可取消/中断本人发起的任务（包括派生子任务）；群主与管理员可中断本群任何任务。权限按处理端当前成员角色与任务发起人校验，不按 Agent 创建者，不信任载荷中的角色或发起人。中断原任务取消其未完成派生任务，不影响其他成员独立任务。停止不等于代批或回滚。远端停止发出后先显示 stopping，收到终态才显示 cancelled；断连时不虚报已停止。已取消的远端请求不得在迟到审批后运行。

## 协议与验证

本版明确与旧版不兼容，应用层协议升级至 v2，拒绝旧应用帧及不匹配的入群协议，不静默降级；加密/握手信封仍沿用现有 v1。字段增加到 IPC、WebSocket 与快照整条链路。任务状态供所有窗口查看，写权限和转交审批只允许应审批用户操作。

测试覆盖：真实 Store 多审批、不受粘贴与文件名触发的提及、真实 RoomService 多成员越权停止/队列/取消竞态、通知与交办分离、三档审批、执行端只读门禁、远端停止确认。最后跑桌面与共享包完整测试、类型检查、构建、diff 检查、样式哈希核对；无法进行的实机测试明确记录。
