# AgentOS Foundation：产品定位、复用策略与群聊协作路线

日期：2026-09-07  
工作分支：`agentos-foundation`  
状态：讨论整理稿，待用户审阅。本文是总体方向与阶段验收约定，不是已经完成的实现说明，也不替代各阶段的详细技术规格。

## 1. 核心结论

以当前 CPA + Claude Code 项目为基础，实际吸收 AionUi、CC Switch、CPA 等项目中可合法复用的代码，将主要研发投入集中在群聊协作。

不从零建设另一个多模型客户端，也不为了抽象而重写已有运行时、代理、配置或 Skills 管理能力。先审计可复用实现，再围绕当前群聊做最小适配。

产品定位：让用户保留自己的服务选择、技能、记忆和工作成果；让不同成员、不同设备上的 Agent 在明确授权下，由主控组织完成协作任务。

统一接入是基础，群聊协作是重点，用户资产连续性是长期价值，Mod 是后续扩展方式。

## 2. 已确认的产品决策

| 事项 | 决策 |
| --- | --- |
| 项目基础 | 在现有 CC 仓库演进，保留 CPA + Claude Code，不另起项目重写 |
| 复用方式 | 不止参考设计；在许可证允许范围内实际复用代码，并保留来源和上游版本 |
| 协作组织 | 第一版一个主控 Agent + 多个子代理；可借鉴复用已有编排实现 |
| 数量模型 | 支持 N 名成员、N 台设备、N 个 Agent；没有写死两台或两种的业务限制，实际容量需验证 |
| 执行位置 | 管理员或群主配置派发位置；成员设备、目录、账号须由所有者授权 |
| 运行中变更 | 不迁移正在执行的任务；默认位置变更仅影响后续任务 |
| 账号管理 | 资源所有者的本地服务统一准入、排队、统计和广播状态 |
| 工作空间 | 用户选择受控共享目录或隔离工作目录，运行中的任务不切换模式 |
| 编辑事务 | 一个 Agent 完成一个当前执行任务的编辑算一个事务，而不是每次工具调用一个事务 |
| 记忆与 Skills | 独立保存用户资产，优先复用管理代码，再深化权限、依赖检查和任务交接 |
| Mod | 第一版不建设万能 Mod 平台；保留当前项目已有能力，后续逐步开放内核接口 |

## 3. 服务接入：CPA 与官方直连并存

区分执行底座与服务连接：

- 执行底座：Claude Code、Codex 等负责实际执行的运行时。
- 服务连接：官方认证链路，或 CPA 中配置的 API / 可代理服务连接。

内部运行配置应能表达底座、连接、模型与权限；仅展示已验证兼容的组合，不承诺任意服务都能连接任意运行时。

### 3.1 CPA 内化

保留并吸收现有代理、认证、日志、配额、模型发现及生命周期管理。先封装或复用，不立即重写。用户最终管理的是 AgentOS 的服务连接，不必维护割裂的多套配置界面。

### 3.2 官方直连

对需要保留官方认证链路的服务，通过受支持的运行时接口接入用户完成官方登录后的执行能力，不把抽取官方凭证再转发作为默认方案。

代理接入、官方登录和跨成员使用的技术可行性，不等于对应服务允许该使用方式；开放连接时需要核实适用规则。用户确认不能覆盖服务本身的限制。

## 4. 代码复用策略

| 来源 | 优先审计的候选能力 | 不预先作出的承诺 |
| --- | --- | --- |
| AionUi | 多 CLI 接入、会话和事件适配、审批、主控与子代理编排 | 不认定所有模块可以原样抽取，或其团队模式已等于跨成员协作 |
| CC Switch | 服务切换、配置、Skills/MCP 管理、代理与用量管理 | 不把配置同步当成分布式派单，也不默认要求用户额外安装它 |
| CPA | 当前代理、认证、模型、配额和日志 | 不重新建设功能相同的网关 |
| 当前 CC | 群聊、成员、附件、远程执行、权威状态、权限、Mod 基础、桌面交互 | 不以整合为由丢弃已有能力与用户数据 |
| 专项参考实现 | 文件预约与消息、变更归属、检查点 | 协作式锁不等于强制写入隔离，工作区快照不等于任务级安全撤销 |

复用前逐项检查：

1. 固定审计的仓库、提交或发行版本。
2. 核实实际实现、测试、平台支持与文档声明的差异。
3. 核查许可证、版权说明、第三方依赖和分发义务。
4. 比较作为依赖、独立进程或抽取模块的集成成本。
5. 为重叠能力选择一个主要实现，明确配置和存储的唯一管理者。
6. 保留来源、改动记录、上游映射与后续安全修复同步方式。
7. 仅对实际缺口新增代码，不先写通用框架再强迫上游代码适配。

复用清单必须落到具体模块和文件；本文列出的来源是候选，不代表已完成源码、许可证或稳定性审计。

## 5. 群聊协作的职责边界

| 角色或模块 | 职责 |
| --- | --- |
| 用户 | 提出目标、授权资源、确认关键操作与成果 |
| 主控 Agent | 理解目标、拆解任务、提出分配、处理依赖、汇总与整合验证 |
| 子代理 | 执行明确子任务，提交变更、验证结果和阻塞信息 |
| 房间权威服务 | 房间状态、任务记录、派发协调、授权记录、事件分发 |
| 成员本地服务 | 实际执行准入、账号队列、凭证、设备资源和运行时管理 |
| 工作空间服务 | 写入约束、占用队列、基线版本、任务事务、变更通知及回滚 |

主控提出分工，不直接绕过内核授权。子代理第一版不自行无限派生或互相派单，需要协助时上报主控。

子代理是 AgentOS 的协作角色，不要求它是同一厂商原生创建的子进程。它可以位于其他成员设备并采用不同运行时。

主任务表示用户目标；执行任务表示分配给一个 Agent 的具体工作；执行尝试记录重试和续接；成果与编辑事务保留各自归属。主任务汇总子任务，不重复记录一遍相同修改。

## 6. 房间权威与部署

建群时提供两类模式：

- 局域网模式：默认由群主设备承担权威，可进行受控切换。
- 自建服务器模式：服务器承担房间权威，并可同时部署中继；Agent 仍可分散在成员设备或服务器。

当前项目的 `room-relay.ts` 与 `room-relay-server.mjs` 描述的是密文转发中继，不承担房间权威。目标中的服务器模式需要额外部署权威服务，不能仅修改名称或开启现有中继。

中继与权威即便部署在同一机器也要保持职责区分。服务器成为权威后，需要处理房间内容和状态，信任边界不同于只转发密文的中继。

一个房间同一时刻只允许一个有效权威。首版不承诺自动选主或无感迁移；权威切换必须有可验证的交接和旧权威停用过程，避免重复派单。任务执行节点不因权威切换自动迁移。

群主关机的影响取决于是否承载权威服务、执行中的 Agent 或尚需访问的文件。只是聊天客户端关闭，不应取消其他节点上的任务。

## 7. 账号、并发与所有者授权

同一成员账号被多个 Agent 使用时，全部经过该成员的本地服务统一处理。房间不另建复杂的跨设备账号识别系统作为首版前置。

- 本地服务是并发准入和排队的最终判断者，广播只是状态提示。
- 首版可采用保守的账号并发默认值，再按服务规则与所有者配置调整；不认定所有订阅上限相同。
- 多个房间调用同一本地服务时，也共享其队列与预算。
- 凭证不广播；广播必要的可用性、忙碌和经授权的配额状态，不泄露详细账单或敏感请求。
- 用户绕过本地服务直接使用同一账号的活动不在本系统完整控制范围内，不承诺绝对全局限流。

所有者可以撤销授权，但撤销不等于已经停止远程进程。必须得到停止确认或撤销实际写入能力后，才能安全重新分配冲突资源。

## 8. 工作空间策略

### 8.1 受控共享目录

同一权威工作空间内，对冲突写入排队。资源键使用工作空间 ID 与规范化路径，不只使用文件名；不同设备上的同名目录不能自动视为同一物理资源。

保证来自实际写入约束，而不是只要求 Agent 遵守提示。Bash、脚本、原生编辑工具、重命名和批量格式化均可能写文件；不能只拦截名为 Edit 的调用。

无法可靠控制写入的运行时，不应标称支持严格共享写入，可限制为只读或采用隔离模式。文件占用不自动约束数据库、网络发布等外部副作用。

### 8.2 隔离工作目录

任务修改独立副本，以补丁、提交或其他成果形式交接，由受控过程校验和整合。隔离不代表合并后一定正确，仍需联合验证。Git worktree 也不自动隔离数据库、端口与其他外部资源。

两种模式由用户按工作空间选择，不按代码或非代码强制划分。

## 9. 任务级事务与文件占用

一个 Agent 完成一个当前执行任务的编辑，形成一个事务、一个交付记录和一个撤销入口。

流程：

1. 明确任务范围、预期修改文件与当前基线。
2. 申请相关写入权，冲突任务排队。
3. 执行期间持有占用；新增文件范围需要申请扩展。
4. 完成后统一保存差异、修改说明、基线和结果版本、验证证据。
5. 发布变更事件并释放占用，等待者重新读取最新状态后执行。

不按每次 Edit 生成交付记录或正式 Git 提交。内部可以保留崩溃恢复日志，但这些不是用户可见的碎片化事务。

必须处理多文件死锁、取消、超时与异常退出。不能仅因租约超时就授权另一个写者；需要阻止旧执行者继续写入。主控不能占住整个项目再要求子代理申请同一资源。

任务级事务是应用层归属与恢复单位，不承诺任意 CLI 修改天然满足数据库式原子性。共享模式下的半完成状态和读一致性，须在详细规格中明确后才开放并发。

## 10. 修改通知、交付与撤销

### 通知

- 修改者收到事务保存和占用释放结果。
- 等待者收到新版本、修改摘要和差异入口，获得写入权后必须重新读取。
- 已知依赖任务收到相关变更提醒。
- 其他成员按权限查看简短房间动态，不把完整差异无差别注入所有 Agent 上下文。

修改声明是有来源的事实和约束，不是不可推翻的命令。后续任务可以合理修改，但需要遵循权限、解释原因并重新验证。

### 撤销

内部检查点与正式 Git 提交分开设计。不得用全目录暂存或整体恢复实现默认任务撤销，以免包含用户原有修改及其他任务成果。

只逆向处理目标事务的变更；后续任务已修改同一区域或依赖目标成果时，进行冲突检查并要求确认。支持主任务撤销组时，同样检查依赖，不能无条件恢复旧目录。

## 11. 断线恢复原则

- 关闭纯客户端：其他节点继续。
- 执行节点失联：标记失联，重连后核对任务是否仍运行或已完成，不直接换设备重跑。
- 文件资源失联：按任务实际依赖暂停；已授权的副本可按隔离策略继续。
- 权威失联：暂停新派单，已有执行遵守事先定义的断线策略。
- 恢复时补齐事件、去重、核对版本与副作用，不能把“没有收到完成消息”当成“没有执行”。

正式开放跨设备协作前，必须验证网络中断、进程崩溃、权威重启及旧节点重连场景。

## 12. 本地资产与 Mod

本地保存用户和项目的记忆、Skills 原件、任务交接资料与成果。优先复用已有存储和分发实现；自研重点是来源、权限、失效、依赖检查和工作连续性。

切换底座可以继承目标、决策、进度、成果和待办，不承诺原生会话或内部推理状态完全互通。本地保存也不代表永不外发，发送到执行节点或模型服务的资料应受控。

Mod 后置。先通过真实主控协作验证内核，再开放动作、事件、状态和界面能力。Mod 不得读取凭证、绕过审批或直接扩大成员设备权限。

## 13. 分支范围与里程碑

### F0：代码审计与复用选型

属于 `agentos-foundation`。

产出：固定版本的源码审计、许可证清单、模块文件级复用清单、重叠能力取舍、数据兼容方案、上游维护方案和测试基线。

验收：能明确说明每项基础能力复用哪里、怎样接入、为何需要新增代码；没有未经核查的“直接搬入”承诺。

### F1：吸收基础能力，供当前群聊调用

属于 `agentos-foundation`。

产出：保留 CPA + Claude Code，按审计结论吸收第二种运行时及适合的配置、事件、审批与 Skills 能力；提供群聊所需的薄调用边界。

验收：群聊可以调用整合后的执行能力；旧配置、会话和主要功能不退化；上游来源和改动可追溯；无重复配置管理者。

完成后验收合并，再为后续工作建立独立分支，不让 foundation 永久承载所有开发。

### C1：群聊主控任务闭环

主控接收目标、派发子任务、处理阻塞、收取成果并验收。已有编排实现可复用则继续复用。

验收：一个主任务完成真实分工；子任务、执行尝试、成果归属明确。此时不开放未经文件安全验证的共享目录并发写入。

### C2：跨成员、跨节点授权执行

完成节点身份、能力与在线状态、成员资源授权、本地排队、远程派单和成果交接。建设服务器权威模式，保留局域网权威模式。

验收：两名成员、两台设备、两种运行时完成授权接力；这是首条用例，不是产品数量上限。未完成下一阶段前采用隔离或串行写入。

### C3：安全文件协作与任务事务

完成共享/隔离策略、实际写入限制、任务级占用、队列、冲突仲裁、检查点、定向通知和安全撤销。

验收：任务不静默覆盖，撤销不误伤用户和其他任务；覆盖多文件死锁、旧版本写入、取消与崩溃。

### C4：持久化与故障恢复

完成事件补齐、去重、任务核对、失联策略、权威恢复和旧写者隔离。

验收：客户端关闭、断网、执行进程崩溃、权威重启后，不丢已持久化任务、不重复已确认动作、不出现双重写入。满足后发布首版可靠跨设备协作功能。

### C5：深化资产连续性

在复用的 Skills 管理基础上建设记忆权限、来源与失效、兼容性检查、跨底座交接。

验收：暂停任务更换底座或执行者后，依靠交接资料继续，无需用户从头解释；明确提示能力差异。

### C6：开放 Mod

开放已验证的任务动作、事件、状态和权限接口，以实际场景验证扩展能力。

验收：不改内核即可增加一种工作流；Mod 不能绕过权限、账号队列和事务机制。

## 14. 成功指标与非目标

成功看任务交付和可靠性，不看接入数量：

- 新底座接入不要求重写群聊。
- 主控派单与子代理成果可追踪、可验收。
- 跨成员调用有所有者授权，凭证不外借。
- 文件变更归属明确，撤销不误伤。
- 断线后核对恢复，不盲目重跑。
- 用户切换服务时减少重复说明，工作资料与成果连续。

首版不做：任意服务组合兼容、执行中无损热迁移、无限递归 Agent 网络、订阅共享市场、自动高可用选主、万能 Mod 平台、自研模型执行循环，以及与 CPA/上游功能重叠的独立网关。
