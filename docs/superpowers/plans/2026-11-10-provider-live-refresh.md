# Provider 即时刷新、推理档位与 Claude 中转鉴权

## 需求与原因

- 已同步的六个模型应立即显示到打开中的模型配置页，不等待其它离线账号或重新打开设置。
- 自定义服务缺少推理档位元数据时，提供低、中、高、超高、最大五档；界面默认值和实际 SDK 请求一致，切换后下一轮生效。
- Claude 中转 API Key 要保留 Claude Messages 协议。旧 CPA 的自定义地址默认 Bearer，原生实现却统一使用 x-api-key，导致模型发现返回 invalid x-api-key。对应历史行为见 `tools/cpa/8.0.43/config.example.yaml:761`。

## 实现

- [x] `cpaModelCatalog` 改为只读已同步目录；启动和显式同步负责联网，目录读取不再等待全部服务和 SDK 初始化。
- [x] `modelCatalogUpdated` 专用通知覆盖启动、模型 ID 不变时的能力更新和账号失效；设置窗口及聊天组件订阅并清理监听。
- [x] 打开中的设置表单按前次同步基线合并模型增删和默认选择，保留本地未保存编辑；只更新对应保存基线，避免意外覆盖其它设置。
- [x] 自定义服务无档位声明时补五档和 medium 缺省；已有档位、显式空档位及有效默认值优先。
- [x] 自定义 Chat 请求原值传递五档；命名服务的等价官方地址保留官方能力和参数规则。Gemini 使用本机协议的有效等级，xhigh/max 映射 HIGH 并附映射说明。
- [x] SDK 请求采用模型显式选择、目录默认、旧全局设置的优先级；温热会话变更档位后通过保留会话的续接路径在下一轮应用。
- [x] Claude 模型发现和 Messages 使用同一鉴权决策：自动时官方域名 x-api-key，其它服务 Bearer；可显式选择。普通中转 Key 不附加 OAuth beta，OAuth 原流程保持。
- [x] 完成运行中等待重开的取消回归、最终集成检查和构建。

## 已取得的端到端证据

- 隔离的真实 Electron 设置窗口接收六个新增模型后立即显示七项（原有一项加六项）；未保存的 123456 上下文限制仍能正确保存。模型 ID 不变时的目录通知也触发读取。
- 真实 SDK 对本地 x-api-key 与 Bearer 两种 Claude 网关均完成模型同步和 Messages 请求，最终返回 OK。
- 真实 SDK 的 low、medium、high、xhigh、max 均与 HTTP 上游 `reasoning_effort` 原值一致。
- 所有验证使用假凭证和隔离目录，不访问用户配置的实际服务。
